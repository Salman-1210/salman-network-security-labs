## 🔐 Overview & Practical Usecase

A **Site-to-Site IPsec VPN** connects two static networks across an untrusted public network (the Internet) through a secure, encrypted connection (tunnel).

### Scenario:
- **Headquarters (HQ):** Located in US (LAN Subnet: `10.1.1.0/24`)
- **Branch Office:** Located in India (LAN Subnet: `20.1.1.0/24`)

### Why IPsec VPN?
- **Public Internet Risks:** Packets traversing the internet are subject to sniffing, interception, and spoofing.
- **VPN Security Solution:** IPsec wraps internal IP packets into an encrypted tunnel. Even if an attacker captures the traffic over the WAN, they only see garbled ciphertext.

## 🧠 Theoretical Fundamentals: How IPsec Works

IPsec (Internet Protocol Security) relies on a two-phase negotiation process using **IKE (Internet Key Exchange)** protocol:

### 1. Phase 1 (IKE Phase 1 / Main or Aggressive Mode)
- **Goal:** Authenticate the two firewall gateways and establish a secure management channel (ISAKMP SA).
- **Key Elements Negotiated:**
  - **Encryption Algorithm:** AES-128, AES-256, 3DES
  - **Authentication Algorithm:** SHA-256, SHA-1, MD5
  - **Diffie-Hellman (DH) Group:** Group 2, Group 5, Group 14 (determines key exchange strength)
  - **Pre-Shared Key (PSK):** Shared secret passphrase between both gateways.
  - **Lifetime:** Time duration before renegotiating Phase-1 keys.

### 2. Phase 2 (IKE Phase 2 / Quick Mode)
- **Goal:** Establish the actual secure tunnel (IPsec SA) for transporting end-user data between local and remote subnets.
- **Key Elements Negotiated:**
  - **Local Subnet & Remote Subnet:** Defining traffic to be encrypted (Interesting Traffic).
  - **IPsec Encapsulation:** ESP (Encapsulating Security Payload).
  - **Transform Sets:** Data encryption and hashing mechanisms for data payload.
  - **PFS (Perfect Forward Secrecy):** Optional re-negotiation of DH keys for extra security.
